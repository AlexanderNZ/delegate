# Reference: `delegate runs`

`delegate runs` lists each [**run**](../glossary.md#run) of this machine in one table, across each repository. It reads the [**journal**](../glossary.md#journal) of each run, and the lock of each [**run branch**](../glossary.md#run-branch), from each [**state directory**](../glossary.md#state-directory) under the state root of this machine: `DELEGATE_STATE_ROOT`, or else `$XDG_STATE_HOME/delegate` (`~/.local/state/delegate`). Each repository has one directory there. The command needs no git repository, so you can run it from any directory.

```
delegate runs [--json | --watch] [--local] [--timeline]
```

| `--local` | Show only the runs of this machine and read no run index; with DELEGATE_INDEX set, the view lists the runs of the other hosts of the index. |
| `--timeline` | Draw one lane for each run over the last 6 hours, to the latest ETA, in place of the table; it cannot be used with --json. |

## Which runs the table lists

The table lists these runs:

- Each run that has no `run-end`: a run that is `running`, `pausing`, `paused`, `halted` or `stopped`. A run that has no `run-end` is listed however old it is.
- Each run whose `run-end` is in the window: the last 6 hours. Its state is the result of the run, for example `built` or `failed`.
- Each run that failed at start in the window, with the state `failed`. Such a run has a `run.log` and no journal, and its time is the time of the last change of its log.

An older run that ended is not listed.

With `DELEGATE_INDEX` set, the table also lists the runs of the other hosts of the [**run index**](../glossary.md#run-index). See [The other hosts](#the-other-hosts).

A journal that cannot be read is skipped. The command names it on stderr, as `delegate status` does, and lists the other runs.

## The table

The first line is `no run index is set up: these are the runs of this machine`. It shows only when `DELEGATE_INDEX` is not set. It is followed by the two fleet lines, a blank line and the table. The table has one group for this machine. The first row of the group holds the name of the machine, and the totals of its runs that have no `run-end`: the ended [**tickets**](../glossary.md#ticket) summed, the latest ETA, and the tokens summed. Under it, each run has a row, and the rail `│` stands in the column `host`.

### The fleet lines

The two fleet lines sum the runs that have no `run-end`. A run that ended is out of each sum, and so is a run that failed at start, and so is a run of an unreachable host.

```
runs  4 of 4 reachable  █████░░░░░░░░░░░ 33%  3/9 ended  ETA 15:10 · 2 with no ETA  34k new · 126k cache
13:00–14:20  ⚠ 2 in trouble  trend: tickets ended an hour, last 6h · all      ▇ speeding up
```

| Part | Meaning |
|---|---|
| `N of M reachable` | `M` is the runs that have no `run-end`, on this machine and on the other hosts of the run index. `N` is the runs of the hosts that this machine can read. Each run of this machine is reachable. See [The other hosts](#the-other-hosts). |
| The bar and `N%` | The tickets that ended over the tickets of the plan, summed over the runs, and rounded down. It is never the mean of the percentages of the runs. The bar has the 16 cells of the run line of `delegate watch`, and it shows only on a terminal of 100 columns or more. |
| `X/Y ended` | The two sums of the tickets that ended and the tickets of the plan. |
| `ETA` | The latest ETA of the runs that have one, or `-` when no run has one. `· N with no ETA` counts the runs with no ETA, for example a run that is paused or stopped. It is left out when N is 0. |
| `new` and `cache` | Two sums of the tokens. They are never added together, and the line shows no cost. They are left out when no run has a count. |
| `HH:MM–HH:MM` | The local clock time of the earliest start of the runs in the sums, and the local clock time of now. It is not the sum of the times of the runs. |
| `⚠ N in trouble` | The runs with an agent that is idle for 5 minutes or more (the idle time of `delegate watch`), the runs that are `stopped` or `halted`, and the runs that failed at start in the window. A paused run is not in trouble. It is left out when N is 0. |
| `trend: tickets ended an hour, last 6h · all` | The sparkline of the tickets that ended in each hour of the window, summed over the runs in the sums, and then the trend word. See [The trend](#the-trend). |

With no run that has no `run-end`, the first line is `runs  0 of 0 reachable`, and the second line is not there.

| Column | Meaning |
|---|---|
| `host` | The name of this machine on the first row of the group, and the rail on each run row. The name is `DELEGATE_HOST` when it is set, else the short host name. |
| `repo` | The name of the repository: the name part of the name of its state directory. |
| `run` | The short id of the run. |
| `state` | The state of the run, as `delegate status` gives it. A run that failed at start is `failed`. |
| `ended` | The tickets that ended, over the tickets of the plan, as `X/Y`. It is dim for a run that ended. |
| `ETA` | The local clock time `HH:MM` of the end that the run is estimated to reach. It is `-` while the run runs and has no estimate. It is blank when the run is paused, halted, stopped or ended. |
| `slip` | How much later the ETA of the run is now than it was 2 hours ago, as `+55m`, in `warn`. See [The slip](#the-slip). It is blank otherwise. |
| `new` | The new tokens of the run. It is blank when the command cannot read the streams of the run. |
| `cache` | The cache tokens of the run. It is blank when the command cannot read the streams of the run. |
| `trend` | The sparkline of the tickets of the run that ended in each hour of the window, in `dim`. See [The trend](#the-trend). The row of the machine has none. |
| `alert` | What is wrong, at most one value, in `warn`. `⚠ idle <time>` when an agent of the run is idle for the stall time of `delegate watch` (5 minutes) or more. Else `fix-up <round>/<limit>` when a [**fix-up**](../glossary.md#fix-up) round of a ticket or of a [**chain**](../glossary.md#chain) runs. It is blank otherwise. A run that is not `running` or `pausing` has no alert. |
| `do` | The next command. `watch` when the run has an alert. Else `resume` when the run is `paused`, `stopped` or `halted`, `retry` when the run ended `failed`, and `merge` when the run ended `built`. It is blank otherwise. A run that failed at start has none: it has no journal to resume. |

The order of the rows is fixed. The runs that have no `run-end` come first, the newest start first. The runs that ended follow, the newest end first.

When no run is listed, there is no table. The command prints three lines and exits 0:

```
no run index is set up: these are the runs of this machine
runs  0 of 1 hosts have an active run
no run ended in the last 6h
```

The number of hosts is this machine and each other host that the [**run index**](../glossary.md#run-index) has a record of. With no run index, this machine is the one host. With `DELEGATE_INDEX` set, the first of the three lines is not there.

### The other hosts

With `DELEGATE_INDEX` set (see [the run index](run.md#the-run-index)), the table has one more group for each other host of the index, after the group of this machine, in the order of the names of the hosts, with a blank line between two groups. The runs of this machine come from its journals, as before: its own records in the index are not used.

The command reads each other host. For each host it runs `ssh -o BatchMode=yes -o ConnectTimeout=5 <host> delegate runs --local --json`, and `<host>` is the name of the host in the index. So `ssh` must reach each host with no password, and `delegate` must be on the `PATH` of the login shell of that host. The hosts are read at the same time, and the read of one host ends after 10 seconds at the latest. This is the only process that `delegate runs` starts.

A host that gives its document of `format` 1 shows its runs as live runs, as the runs of this machine show. They have the ETA, the `slip`, the tokens, the trend, the `alert` and the `do` word that the host worked out, and they are in the sums of the fleet lines and in `⚠ N in trouble`. The rows of the group of the host are not dim, and the row of the host has its totals. The records of that host in the index are not used. In `--timeline`, such a lane has the life of the run and the projection to the ETA, but not the `●` marks of the tickets, because the document holds the number of the tickets that ended in each hour, not their times.

A host is `unreachable` when its read fails (`ssh` exits with a status other than 0, or cannot start), when the read takes more than 10 seconds, and when the host gives a document that this version cannot read: a `format` other than 1, or text that is not the document. The view does not say which. This machine then shows the last-known values of the records of that host, and nothing else.

For example, a host `build-host` with one run `a41e` that was `running` at 3 of 6 tickets, last heard 47 minutes ago, has these two rows. The first row has `unreachable` in `state`, `heard 47m ago` in `alert` and `check host` in `do`. The second row has `│` in `host`, `docs-site` in `repo`, `a41e` in `run`, `running` in `state` and `3/6` in `ended`, and nothing else.

- The row of the host has the name of the host, the state `unreachable` in `warn`, the `alert` `heard <duration> ago` in `warn` (the time since the host wrote its newest record, in whole minutes, as `47m`, or `3h05m` from an hour), and the `do` word `check host`. It has no totals.
- The rows of its runs are dim and hold the last-known `state` and `ended` of the record. They have no ETA, no `slip`, no tokens, no trend, no `alert` and no `do`.
- A record of a run that ended is listed under its host, with the result as its state, while the time of the record is in the window. A record of a run that ended before the window is not listed, and a host with no listed record has no group.
- The runs of an unreachable host are out of each sum of the fleet lines, and out of `⚠ N in trouble`. The first line counts them in the total: `runs  1 of 3 reachable`.

In `--timeline`, each lane of such a run is dim from the start of the run to the time that its host was heard from. Its `state` is `unreachable` and its `alert` is `heard <duration> ago`.

`--local` limits the view to this machine and reads no index, and starts no `ssh`. `--json` always describes this machine only, reads no index, and starts no `ssh`: this is the document that another host gives. With `--watch`, the command reads the other hosts at most each 30 seconds, and redraws with the last answers between two reads.

[`delegate clean`](commands.md) forgets the record of each run that it cleans or abandons, so the other hosts list it no more.

### The slip

The journal holds no ETA, so the command works out the ETA of 2 hours ago from the events of the journal. The snapshot of the run at that time is the events up to that time, that time, a live process, and no [**pause**](../glossary.md#pause) request. The slip is the ETA now minus the ETA of that snapshot.

It shows as `+<duration>` when it is 30 minutes or more: `+55m`, or `+1h05m` from an hour. It is blank when one of the two ETAs is missing (the run does not run now, or it had no ETA 2 hours ago), when the run started less than 2 hours ago, and when the slip is less than 30 minutes.

### The trend

A ticket counts one time, at the time of its first `step-end` with the state `built`. A ticket that a `retry` revived has a later `step-end` with the state `built`, and that one does not count again.

The trend of a run is 6 cells, one for each hour of the window, oldest first. The last cell is the hour that ends now. Each cell is the number of tickets that ended built in that hour. A ticket that ended before the window is in no cell.

Each cell is one glyph, in `dim`. The glyphs are `▁▂▃▄▅▆▇`, from the lowest level to the highest. The level is scaled to the largest cell of all the runs in the table, so one scale serves each run: a cell of the same size has the same glyph in two runs. A cell with no ticket is a space. When the locale is not UTF-8, the glyphs are `.:-=+*#`, and each takes the same cell.

The `all` sparkline of the second fleet line is the sum of the cells of the runs that have no `run-end`. Its scale is its own largest cell, because the sum can be larger than each cell of one run.

The trend word compares the tickets of the last 2 hours with the tickets of the 2 hours before them. More than 1.25 times as many is `speeding up`. Fewer than 0.75 times as many is `slowing`. Otherwise it is `steady`. When both counts are 0, there is no word.

### The legend

Under the table is a blank line and the legend: one line for each word of the column `do` that the table holds, once, in the order `watch`, `resume`, `retry`, `merge`, `check host`. Each line has the word and its command. A word that is not in the table has no line, and a table with no word has no legend. The legend shows only on a terminal of 100 columns or more.

| Word | Command |
|---|---|
| `watch` | `delegate watch <run>` |
| `resume` | `delegate run --resume <run>` |
| `retry` | `delegate run --resume <run> --retry <ticket>` |
| `merge` | `git merge --ff-only <run branch>` |
| `check host` | `ssh <host>` |

When a host other than this machine has a `do` word in the table, the last line of the legend ends with `; on another host, put ssh <host> in front of each command`. An unreachable host has the word `check host`, so the legend has it then.

Each command works from any directory of this machine: `delegate watch` and `delegate run --resume` find the run by its id, and the journal records the repository of the run. Put the short id of the run in `<run>`.

## Fit to the terminal

The command reads the size of the terminal: `COLUMNS` and `LINES`, else the size of the terminal that is standard output. When the terminal gives no width, the width is 80. When it gives no height, no row folds.

**Width.** Under 100 columns, the bar and the legend drop. Then, while the widest line of the table is wider than the terminal, the columns drop in this order: `new` and `cache`, then `trend`, then `slip`, then `repo`. The first fleet line drops its token sums when it is wider than the terminal, and the second fleet line drops the words and the sparkline of the trend when it is wider than the terminal. The trend word stays. Each line is then cut to the width.

**Height.** When the lines are more than the lines of the terminal, less one line for the prompt, the rows fold in two stages. The command goes to the next stage only when the lines still do not fit:

1. The runs that ended fold into one row, with the glyph of the first state and the count of each state, for example `✓ 1 built` or `✗ 1 failed`. The text starts in the column `state`. A run that ended is out of the totals, so the totals do not change. The legend then holds only the words of the rows that show.
2. When the runs that have no `run-end` have no alert and no command, the host folds to its totals row: no run row shows.

A host with an alert or a command does not fold to its totals row. When the lines still do not fit, the command prints them all.

**Colour and glyphs.** With `NO_COLOR` set and not empty, or when standard output is not a terminal, the output has no colour code. When the locale is not UTF-8, each glyph is its ASCII glyph, and each ASCII glyph has the width of the Unicode glyph, so the columns are in the same positions. The title of the terminal is not a colour code: `DELEGATE_NO_TITLE=1` turns it off.

## The option `--timeline`

`delegate runs --timeline` shows the same two fleet lines, and then one lane for each run in place of the table. A lane shows the time of a run across the window, the last 6 hours, and on to the latest ETA of the runs. It shows the same runs in the same order as the table. `--timeline` can be used with `--watch`, and it cannot be used with `--json`.

The legend is the end of the second fleet line, after the trend word. Under 100 columns it is only `one cell is 12m`. The header under the blank line holds the label `last 6h, to the latest ETA` and the headers `ended`, `ETA`, `state` and `alert`. The first lane is `all` (see below). Each lane row after it has the label `host repo run` (the host on the first row, the rail `│` under it), the lane, and then `ended`, `ETA`, `state` and `alert` as in the table. Under the lanes, after a blank line, is the footer `detail  delegate watch <run>; on another host, ssh <host> delegate watch <run>`.

The lane `all` is the sparkline of the tickets that ended built in each cell of the window, over all the runs that have no `run-end`, on a scale whose largest cell has the top level; then the column of now `┊`, and `░` to the latest ETA. Its `ended` and `ETA` are the totals of those runs, as on the row of the host in the table. A run that ended is out of the lane `all`.

**Under 100 columns** the label of a lane is the run id only, and the host is a line over its lanes, under the lane `all`. The column `ETA`, the label `last 6h, to the latest ETA` and the footer drop, as the bar and the legend of the table drop.

One cell is 10 minutes on a terminal of 120 columns or more, and 12 minutes on a narrower one. Cell 0 starts at the start of the window, now minus 6 hours. The window has 36 cells of 10 minutes, or 30 cells of 12 minutes. The cell after them is the column of now, and the cells after that are the projection. The lane ends at the latest ETA of the runs, or at the column of now when no run has an ETA. A time is in the cell that holds it. A time before the window is in cell 0, and a time after now is in the last cell of the window.

| Glyph | ASCII | Role | Meaning |
|---|---|---|---|
| `─` | `-` | none | The life of the run, from the cell of its start. |
| `●` | `*` | `ok` | A ticket that ended built, in the cell of its first `step-end` built (the rule of [The trend](#the-trend)). |
| `✓` or `✗` | `+` or `x` | `ok` or `bad` | The end of a run that ended, in the cell of its `run-end`: `✓` for `built`, `✗` for each other result. A run that is `stopped` or `halted` ends with `✗` in the cell of its newest event. A run that failed at start is one `✗` in the cell of its log. A `paused` run ends in the cell of its newest event, with no mark. |
| `▶` | `>` | `now`, or `warn` | Now, for a run that is `running` or `pausing`. It is `warn` when the run has an alert. |
| `░` | `.` | `dim` | The projection of a run that runs, from now to its ETA. |
| `┊` | `:` | `now` | The present, for each run that does not run. It is in the same column in each lane. |

The command fits the lanes to the width of the terminal only as far as the cell size and the columns that drop under 100 columns. The folds of the rows to the height of the terminal do not apply to `--timeline`.

## The option `--watch`

`delegate runs --watch` shows the same view (with `--timeline`, the lanes), and redraws it in place once a second, the poll rate of `delegate watch`. The command lists the state root again at each redraw, so a run that starts, or that is cleaned away, shows or goes at the next redraw. It reads each journal again only from the position where it stopped, not from the start.

- The frame replaces itself in place. The command does not use the alternate screen, so the last frame stays in the scrollback. The first frame hides the cursor, and each end of the command shows it again.
- A redraw writes only the lines that changed, and nothing when the frame is the frame before, as the live view of `delegate watch` does. The view has no spinner.
- The command reads the size of the terminal at each redraw, so the frame follows a new size. It fits the width and the height as [Fit to the terminal](#fit-to-the-terminal) says.
- A journal that cannot be read goes on stderr one time. The command names it before the first frame when the first read finds it. A journal that breaks later is named after the last frame, so no line of stderr breaks a frame.
- Ctrl-C, SIGTERM and SIGHUP end the command. It prints `delegate: interrupted` on stderr and exits with 130, with no traceback.
- When standard output is not a terminal, the command prints `delegate runs: --watch needs a terminal` on stderr and exits with 2. `--watch` and `--json` exclude each other.

## The JSON object

`--json` prints one object. The object is a contract with a version: a later version can add a field, and a change to a field needs a new `format`.

```json
{
  "format": 1,
  "host": "laptop",
  "time": "2026-11-14T14:20:00+00:00",
  "window_seconds": 21600,
  "runs": [
    {
      "run_id": "20261114T134000Z-aaaa",
      "repo": "alpha",
      "host": "laptop",
      "state": "running",
      "started": "2026-11-14T13:40:00+00:00",
      "ended": null,
      "tickets_ended": 1,
      "tickets_total": 2,
      "eta": null,
      "tokens_new": 12000,
      "tokens_cache": 340000,
      "alert": null,
      "do": null,
      "trend": [0, 0, 0, 0, 0, 1],
      "slip_seconds": null
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `format` | The version of the contract. It is `1`. |
| `host` | The name of this machine. |
| `time` | The time of the command, in UTC. |
| `window_seconds` | The length of the window of the runs that ended: 21600, which is 6 hours. |
| `runs` | One object for each listed run, in the order of the table. |
| `run_id` | The full id of the run. |
| `repo` | The name of the repository. |
| `host` | The name of this machine. |
| `state` | The state of the run. |
| `started` | The time of the `run-start` of the run, in UTC. For a run that failed at start, the time of the last change of its log. |
| `ended` | The time of the `run-end` of the run, or `null` for a run that has none. For a run that failed at start, the time of the last change of its log. |
| `tickets_ended` | The tickets that ended. |
| `tickets_total` | The tickets of the plan. |
| `eta` | The estimated end of the run, or `null` when the run does not run or has no estimate. |
| `tokens_new` | The new tokens of the run, or `null` when the command cannot read its streams. |
| `tokens_cache` | The cache tokens of the run, or `null` when the command cannot read its streams. |
| `alert` | The text of the column `alert`, or `null`. The glyph of `⚠ idle` is always `⚠`, also in a terminal that is not UTF-8. |
| `do` | The word of the column `do`, or `null`. |
| `trend` | The 6 counts of the trend of the run: the tickets that ended built in each hour of the window, oldest first. |
| `slip_seconds` | The slip of the ETA in seconds, or `null` when the column `slip` is blank. |

## Exit codes

| Code | Condition |
|---|---|
| 0 | The command printed the table or the object, also when no run is listed. |
| 2 | The state root is not an absolute path, a lock file cannot be read, or `--watch` has no terminal for standard output. |
| 130 | Ctrl-C ended `--watch`. |
