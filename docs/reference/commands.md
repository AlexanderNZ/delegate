# Reference: `delegate render`, `validate`, `bootstrap` and `brief`

These four subcommands of `delegate` take the arguments of the standalone commands `agent-definitions` (`render`, `validate`, `bootstrap`) and `verifier-brief` (`brief`). The exit code, the output and the files written are the same for the two spellings: `delegate render ...` is `agent-definitions render ...`, and `delegate brief ...` is `verifier-brief ...`. The tables of options on this page are generated from the argument parsers by `delegate docs`. See [`delegate docs`](docs.md).

The skill [`agent-definitions`](https://github.com/AlexanderNZ/delegate/blob/main/skills/agent-definitions/SKILL.md) holds the rules that the commands apply: the rendering rules, the tier table, and the rules of the verifier's shell.

## `delegate render`

```
delegate render <declaration> -o <out> [--opencode-model <tier=model>] [--opencode-allow <model>]
```

`render` reads a declaration (TOML) and writes the agent files for each harness into `<out>/claude-code` and `<out>/opencode`. It prints the path of each file that it wrote, and exits 0.

<!-- generated:begin render-options -->
<!-- Generated by `delegate docs`. Do not edit this section by hand. -->

| Option | Meaning |
|---|---|
| `<declaration>` | The declaration file (TOML) to render. Required. |
| `-o, --out <out>` | The output directory; it receives the subdirectories claude-code and opencode. Required. |
| `--opencode-model <tier=model>` | Use MODEL for TIER in the OpenCode column; repeat it. |
| `--opencode-allow <model>` | Add MODEL to the OpenCode allowed set; repeat it. It extends the set, never replaces it. |

## `delegate validate`

```
delegate validate [<rendered>] [--claude-code <dir>] [--opencode <dir>] [--skills-dir <dir>] [--user-skills-dir <dir>]
```

`validate` checks rendered agent files against the schema of each harness. It prints one line for each finding, and then `N finding(s)` on stderr, and exits 1. It prints `ok` and exits 0 when there is no finding. With no directory to check it exits 2. See [the finding codes](#the-finding-codes).

<!-- Generated by `delegate docs`. Do not edit this section by hand. -->

| Option | Meaning |
|---|---|
| `[<rendered>]` | A root with claude-code/ and opencode/ subdirectories. |
| `--claude-code <claude-code>` | A directory of rendered Claude Code agents to validate. |
| `--opencode <opencode>` | A directory of rendered OpenCode agents to validate. |
| `--skills-dir <skills-dir>` | Check that every preloaded skill exists here. |

| `--opencode-allow <model>` | Add MODEL to the OpenCode allowed set; repeat it. It extends the set, never replaces it. |

## `delegate bootstrap`

```
delegate bootstrap --repo <dir> --name <name> --domain <text> --tier <tier> --skill <name> --reference <path> [...]
```

`bootstrap` writes the context skill of a repository, its declaration, and the rendered pair. With `--dry-run` it prints each file with its content and writes nothing. It exits 0 when it wrote the files, and 1 on a problem that the message on stderr names.

## `delegate brief`

```
delegate brief full --repo <dir> --branch <branch> --task <text> [--base <base>] [--stack <heading>]
delegate brief fixup --repo <dir> --branch <branch> --rejected <commit> --findings <file> [--authorised <text>] [--stack <heading>]
```

`brief` prints the brief of a verifier. The shape of the brief sets the mode of the verifier: `full` is a first pass, and `fixup` is a scoped pass over the delta since the rejected commit. It exits 0, or 1 when git or a file cannot be read.

## The verifier guard

`render` writes a guard into each verifier. The guard permits the commands in the table below, and no other. The rules that apply to the commands, the gate commands of a repository and the limits of the guard are in [the skill](https://github.com/AlexanderNZ/delegate/blob/main/skills/agent-definitions/SKILL.md#the-verifiers-shell).

<!-- generated:begin verifier-guard-commands -->
<!-- Generated by `delegate docs`. Do not edit this section by hand. -->

| Group | Commands |
|---|---|
| git reads | `git diff`, `git log`, `git show`, `git status`, `git ls-files`, `git ls-tree`, `git rev-parse`, `git merge-base`, `git worktree list`, `git branch --show-current` |
| shell reads | `ls`, `cat`, `head`, `tail`, `sed -n`, `grep`, `rg`, `find`, `wc`, `diff`, `jq`, `shasum`, `stat`, `readlink`, `file`, `which`, `env`, `pwd`, `echo`, `printf`, `date`, `mktemp`, `python3`, `bash -c` |
| temp writes | `mkdir`, `mv`, `rm`, `tee`, `touch` — each one only when every path argument starts with `/tmp/`, `/private/tmp/`, `$TMPDIR`, or `/var/folders/`. A redirection target obeys the same rule, in every segment. |
| temp destination | `cp`, `cd` — each one only when the last path argument is a temp path. The earlier path arguments are sources, and a read of any path is a read. |

<!-- generated:end verifier-guard-commands -->

## The finding codes

`validate` writes one line for each finding: the code, the file, and a message. The code is one of these.

<!-- generated:begin finding-codes -->
<!-- Generated by `delegate docs`. Do not edit this section by hand. -->

| Code | Meaning |
|---|---|
| `UNKNOWN_KEY` | a frontmatter key the harness does not recognise; inert on Claude Code, swept into provider options on OpenCode |
| `BAD_MODEL` | model not in the tier table's allowed set for that harness |
| `BAD_EFFORT` | Claude Code `effort` outside the levels, or OpenCode `variant` outside the variants |
| `MISSING_TWIN` | a `-specialist` without its `-verifier`, or the reverse |
| `DUPLICATE_NAME` | two files declare one name; the harness picks one by filesystem read order |
| `VERIFIER_WRITE_TOOL` | a verifier lists Edit, Write, MultiEdit, NotebookEdit, or an unguarded Bash; on OpenCode it permits a write tool with `allow` or `ask`, or its `bash` map does not open with `"*": deny`, or that map resolves a write command to allow |
| `VERIFIER_BASH_UNGUARDED` | a Claude Code verifier lists `Bash` with no `PreToolUse` hook on Bash whose command carries `# agent-definitions:verifier-guard` |
| `RULE_SHADOWED` | an OpenCode permission rule placed before `"*"` in the same map; the last matching rule wins, so it does nothing |
| `VERIFIER_NOT_READONLY` | a Claude Code verifier with no `tools` allowlist; an OpenCode verifier whose first rule is not `"*": deny` |
| `SPECIALIST_CAN_PUSH` | a `-specialist` with no push guard: on Claude Code no `PreToolUse` hook that selects Bash and names `push`; on OpenCode no `permission.bash` deny that covers `git push`. A deny that the catch-all shadows does not count |
| `BAD_FRONTMATTER` | frontmatter absent on line 1, unclosed, or not YAML |
| `NAME_INVALID` | a name that starts with a hyphen or holds a character outside letters, digits, hyphen and underscore, so the harness would skip the file |
| `MISSING_NAME` | a Claude Code file with no name; the harness treats it as documentation |
| `MISSING_DESCRIPTION` | a name with no description; the harness skips the file, and OpenCode needs a description for routing |
| `BAD_TYPE` | OpenCode `tools` as a string; that aborts config load for the whole session |
| `CROSS_HARNESS_MISMATCH` | an agent present for one harness and absent for the other |
| `MISSING_SKILL` | a preloaded skill absent from `--skills-dir` |
| `DESCRIPTION_BUDGET` | combined Claude Code descriptions exceed the budget in `tiers.toml` |

<!-- generated:end finding-codes -->
