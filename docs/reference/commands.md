# Reference: `delegate render`, `validate`, `bootstrap` and `brief`

These four subcommands of `delegate` take the arguments of the standalone commands `agent-definitions` (`render`, `validate`, [**`bootstrap`**](../glossary.md#bootstrap)) and `verifier-brief` (`brief`). The exit code, the output and the files written are the same for the two spellings: `delegate render ...` is `agent-definitions render ...`, and `delegate brief ...` is `verifier-brief ...`. On a terminal, the `delegate` spelling also sets the title of the terminal to `delegate <subcommand>`, for example `delegate render`, and the standalone commands set no title. See [the terminal title](status-and-watch.md#the-terminal-title). After Ctrl-C, the `delegate` spelling prints `delegate: interrupted` on stderr and exits 130. The standalone commands do not catch Ctrl-C. The tables of options on this page are generated from the argument parsers by `delegate docs`. See [`delegate docs`](docs.md).

The [**skill**](../glossary.md#skill) [`agent-definitions`](https://github.com/AlexanderNZ/delegate/blob/main/skills/agent-definitions/SKILL.md) holds the rules that the commands apply: the rendering rules, the [**tier table**](../glossary.md#tier-table), and the rules of the [**verifier**](../glossary.md#verifier)'s shell.

## `delegate render`

```
delegate render <declaration> -o <out> [--opencode-model <tier=model>] [--opencode-allow <model>]
```

`render` reads a [**declaration**](../glossary.md#declaration) (TOML) and writes the agent files for each [**harness**](../glossary.md#harness) into `<out>/claude-code` and `<out>/opencode`. It prints the path of each file that it wrote, and exits 0.

## `delegate validate`

```
delegate validate [<rendered>] [--claude-code <dir>] [--opencode <dir>] [--skills-dir <dir>] [--user-skills-dir <dir>] [--opencode-model <tier>=<model>] [--opencode-allow <model>]
```

`validate` checks rendered agent files against the schema of each harness. It prints one line for each [**finding**](../glossary.md#finding), and then `N finding(s)` on stderr, and exits 1. It prints `ok` and exits 0 when there is no finding. With no directory to check it exits 2. See [the finding codes](#the-finding-codes).

| `--opencode-model <tier=model>` | Use MODEL for TIER in the OpenCode column; repeat it. |
| `--opencode-allow <model>` | Add MODEL to the OpenCode allowed set; repeat it. It extends the set, never replaces it. |

<!-- generated:end validate-options -->

With `--skills-dir`, `validate` also reads each skill that a Claude Code agent preloads, in `--skills-dir` and in `--user-skills-dir`, and checks each load-time block: a fenced block that opens with `` ```! ``. A block that holds `$(`, a backtick, `;`, `&&`, a double pipe, a pipe, `if` or a redirection outside quotes gives the finding `LOAD_BLOCK_NOT_PLAIN`, with the file and the line. One plain command passes, for example `sed -n '1,20p' docs/gates.md`. A sign in single quotes is text, so `grep -n -E 'a|b' docs/gates.md` also passes. The rule comes from [**ADR**](../glossary.md#adr) 0006, `docs/adr/0006-load-time-blocks-are-one-plain-command.md`. A skill that carries the line `<!-- agent-definitions:context-load read -->` was written with `contextLoad = "read"`, and each load-time block in it gives the finding `LOAD_BLOCK_IN_READ_SKILL`, with the file and the line, also when the block is one plain command.

## `delegate bootstrap`

```
delegate bootstrap --repo <dir> --name <name> --domain <text> --tier <tier> --skill <name> --reference <path> [...]
```

`bootstrap` writes the [**context skill**](../glossary.md#context-skill) of a repository, its declaration, and the rendered pair. With `--dry-run` it prints each file with its content and writes nothing. It exits 0 when it wrote the files, and 1 on a problem that the message on stderr names.

Each load-time block of the context skill is one plain command. A block with `$(...)`, `;`, `if` or a pipe stopped a subagent from starting with each of the `--permission-mode` values `default` (manual), `acceptEdits` and `auto`, measured on Claude Code 2.1.283 on 2026-09-26. No Claude Code documentation states this rule: it is a measured behaviour. [**ADR**](../glossary.md#adr) 0006, `docs/adr/0006-load-time-blocks-are-one-plain-command.md`, records the measurements and their source. See [the decision records](../explanation/decision-records.md). The context skill carries the same note.

With `--context-load read`, the declaration gets `contextLoad = "read"`, and the context skill has no load-time block. Its first instruction tells the agent to read each reference with the Read tool before any other step, in the order of the references, and to stop and report when a reference is missing. Use it on a host where a load-time block cannot run. `--context-load blocks` writes `contextLoad = "blocks"` and the skill of the default. Any other value exits 1 and names the permitted values, `blocks` and `read`. Without the flag, the declaration holds no `contextLoad` key, and the files are the same bytes as before the flag existed.

## `delegate brief`

```
delegate brief full --repo <dir> --branch <branch> --task <text> [--base <base>] [--stack <heading>]
delegate brief fixup --repo <dir> --branch <branch> --rejected <commit> --findings <file> [--authorised <text>] [--stack <heading>]
```

`brief` prints the [**brief**](../glossary.md#brief) of a verifier. The shape of the brief sets the [**mode**](../glossary.md#mode) of the verifier: `full` is a first pass, and `fixup` is a scoped pass over the [**delta**](../glossary.md#delta) since the rejected commit. It exits 0. It exits 1, and names the cause on stderr, when git or a file cannot be read, when the diff or the [**fix-up**](../glossary.md#fix-up) delta is empty, when the rejected commit is not an ancestor of the branch, or when a `--stack` heading names no [**gate**](../glossary.md#gate) block. It exits 2 on a usage error.

## The verifier guard

On Claude Code, `render` writes two guards into each verifier: a guard on Bash and a guard on the Write tool. Together they permit the commands and the writes in the table below, and no other. The rules that apply to the commands, the [**gate**](../glossary.md#gate) commands of a repository and the limits of the guard are in [the skill](https://github.com/AlexanderNZ/delegate/blob/main/skills/agent-definitions/SKILL.md#the-verifiers-shell).

<!-- generated:begin verifier-guard-commands -->
<!-- Generated by `delegate docs`. Do not edit this section by hand. -->

| Group | Commands |
|---|---|
| git reads | `git diff`, `git log`, `git show`, `git grep`, `git status`, `git ls-files`, `git ls-tree`, `git rev-parse`, `git merge-base`, `git worktree list`, `git branch --show-current` |
| shell reads | `ls`, `cat`, `head`, `tail`, `sed -n`, `grep`, `rg`, `find`, `wc`, `diff`, `jq`, `shasum`, `stat`, `readlink`, `file`, `which`, `env`, `pwd`, `echo`, `printf`, `date`, `mktemp`, `python3`, `bash -c` |
| temp writes | `mkdir`, `mv`, `rm`, `tee`, `touch` — each one only when every path argument starts with `/tmp/`, `/private/tmp/`, `$TMPDIR`, or `/var/folders/`. A redirection target obeys the same rule, in every segment, but it can also be exactly `/dev/null`, which writes no file: `2>/dev/null` is permitted. |
| temp destination | `cp`, `cd` — each one only when the last path argument is a temp path. The earlier path arguments are sources, and a read of any path is a read. A `cd` takes one path argument, and it may also go to a directory in the git toplevel of the working directory, with no `..` component: `cd api && ./gradlew test`. |
| Write tool | `Write` — only when `file_path` is an absolute path that starts with `/tmp/`, `/private/tmp/`, or `/var/folders/`, or with the value of `$TMPDIR` in the environment of the hook, and has no `..` component. |
| git trees | No temp write, no `cp` destination, no redirection target, no output path and no `Write` may be inside a git tree, or hold one. A git tree is a directory that holds a `.git` entry: the git toplevel of the working directory of the hook, and each directory with a `.git` entry above a write target or in it. The working directory is the `cwd` of the hook input, or else the working directory of the process. The guards compare the paths after they remove a `/private` prefix on both sides, so a worktree in a temp directory stays read-only. A `cd` may go to the git toplevel of the working directory. |

<!-- generated:end verifier-guard-commands -->

A `cd` writes nothing, so it may go to a temp path or to a directory in the git toplevel of the working directory. Many repositories give their gates in the form `cd <dir> && <gate>`: with the gate `./gradlew test`, `cd api && ./gradlew test` is permitted. A `cd` takes one path argument. A relative path must have no `..` component, and an absolute path must be the toplevel or a path in it. The guard denies a path that starts with `~` or `=`, and a path with `*`, `?`, `[`, `{` or `$`. So `cd ../outside`, `cd /etc`, `cd api/../..` and `cd ~` are denied. Each later segment is tested on its own, so `cd api && echo x > f` stays denied: `f` is not a temp path. With no git toplevel above the working directory, only a temp path is permitted. The rule reads text, so a symbolic link in the tree, a `CDPATH` of the shell, or a directory with its own `.git` entry can take the working directory out of the tree. The guard still denies each write outside a temp directory.

A segment that starts with `docker compose` loses each `-f <file>` and `--file <file>` that comes directly after it, as a segment that starts with `git` loses `-C <path>`. With the gate `docker compose config`, `docker compose -f compose.yml config` is permitted. The subcommand after the options is still tested, so `docker compose -f x.yml up` and `docker compose -f x.yml run app sh` stay denied.

A segment that starts with `env` loses `env` and its options `-i`, `-0`, `-u <name>`, `-` and `--`, and the guard tests the rest as its own command, with every rule (#158). So `env touch <file>`, `env -i rm <file>` and `env bash -c '<cmd>'` are denied, and `env`, `env -0` and `env | grep PATH` are permitted. A bare `env`, or `env` with only options and `NAME=value` assignments, is a read. An assignment before a command is denied, as an assignment prefix without `env` is: `GIT_EXTERNAL_DIFF=touch` makes `git diff` write files, and `GIT_CONFIG_*` and `PATH` can do the same. The guard also denies each other option of `env` (`-S` runs a string as a command, `-C` changes the directory), a word before the command with a quote, a backslash, an expansion or a pattern character, and `bash -c` or `python3` after `env`.

Three read commands of the table can run a command or write a file, so the guard examines their words (#158). After `find`, it denies `-exec`, `-execdir`, `-ok`, `-okdir`, `-delete`, `-rm`, `-fprint`, `-fprint0`, `-fprintf` and `-fls`. After `rg`, it denies `--pre` and `--hostname-bin`, in each form. `sed -n` is permitted only as a line range: `sed -n '<start>,<end>p' <path>`, with digits, `$` as the last address in single quotes, and paths with no option, quote, backslash, expansion or pattern character. A sed script can run a command (the GNU `e` command) or write a file (`w`), and `-i` edits a file in place, so the guard denies each other form of `sed -n`. To search for a pattern, use `grep`. Commands that run another command and are not in the table, such as `xargs`, `nice`, `nohup`, `timeout`, `time`, `command` and `exec`, are denied.

A redirection with `&` must go to a file descriptor, not to a file. The guard permits `>&` and `n>&` only when the word after the `&` is a file descriptor number or `-`: `2>&1`, `>&2`, `>&1` and `>&-` are permitted. With another word, bash, `/bin/sh` and zsh write the output to a file of that name, so the guard denies `ls >&src/out`, `ls >& out`, `cat x >& rm -rf src` and `ls 2>&out`. It denies each `>>&`, because zsh then appends to a file, also with a number. A segment that ends at a redirection sign is also denied: in `ls >|cat` and `ls >&|cat`, the shell writes the file `cat`. The guard reads a quoted search pattern as text too, so it also denies `grep -F '2>&1' src`. To search for the text `2>&1`, write a `.` in place of the `>`: `grep -n '2.&1' src`. The guard divides a segment into words at spaces, also inside quotes, so in `bash -c "ls 2>&1"` the word after the `&` is `1"`. A quote there can make the target a file name, as in `ls >&1")"`, which writes the file `1)`. So the guard denies the word, and its message tells the agent to put a space before the closing quote: `bash -c "ls 2>&1 "` is permitted under bash, `/bin/sh` and zsh.

Each guard keeps the verifier read-only on the tree under review and on each other git tree, also when the tree is in a temp directory. On macOS, a [**worktree**](../glossary.md#worktree) from `mktemp -d` is under `/var/folders`, which is a link to `/private/var/folders`. A git tree is a directory that holds a `.git` entry: a directory, or a file that points to a git directory. The guard finds the git toplevel of its working directory: the nearest directory, from the working directory up, that holds a `.git` entry. It also looks for a `.git` entry from each write target up, and in the directory that the target names (#125), so a verifier whose working directory is a copy with no `.git` entry cannot write into the original tree. It reads the file system in the `python3` process that it starts to read the hook input, so it starts no git process. The walk in a directory reads at most 2000 directories. When it stops at that limit, a target that is the directory or holds it is denied, because the guard cannot tell that the directory holds no git tree. The Bash guard then denies each temp path that is inside a git tree, or that holds one, as a write target: `cp /tmp/x <file>`, `echo x > <file>`, `tee <file>`, `rm <file>`, `mkdir <dir>` and `touch <file>` are denied, and so is `rm -rf` of a directory that holds a git tree. Before it compares, it reads the path as the shell will: it removes each quote and backslash, puts the value of `$TMPDIR` in place of a leading `$TMPDIR`, and makes each `//` and `/./` one `/`. For a path with a pattern or an expansion character (`*`, `?`, `[`, `{` or `$`), only the text before the first such character counts. The Write guard denies a `file_path` inside a git tree, or that holds one, in the same way. A write to another temp path stays permitted, so a verifier can still copy the tree into a temp directory, remove the `.git` entry of the copy in the same command, and change the copy. The working directory of a `delegate run` verifier is the temporary copy of the engine, and it writes its verdict beside the copy, not in it. For a red proof, the engine makes the proof copy beside the temporary copy, with no `.git` entry, and the verifier goes to it with `cd` (#153). A verifier outside a `delegate run` makes its own copy: the copy and the removal of the `.git` entry of the copy are one command from the working directory, `cp -R <tree> /tmp/x && rm -r /tmp/x/.git`, and the `cd /tmp/x` comes after it. A copy that holds a `.git` entry is a git tree, so the guard denies the removal of that entry in a later command.

The guard does not parse a nested shell. So the rendered verifier states a rule that the guard does not enforce: a command that the guard refuses is not run in another form, through `bash -c`, `python3 -c`, `sh -c`, `env`, `xargs` or a script file. The verifier reports the refusal in `unverified`, with the command and the message of the guard. See [the enforcement model and its limits](../explanation/the-enforcement-model-and-its-limits.md).

The verifier writes its [**verdict**](../glossary.md#verdict) with the Write tool. On Claude Code the verifier lists `Write` in `tools`, and a `PreToolUse` hook on `Write` reads `tool_input.file_path` with `python3`. The hook permits the Write only when the path is absolute, starts with a temp prefix of the table or with the value of `$TMPDIR` in its environment, has no `..` component, is not inside a git tree, and does not hold one. A `$TMPDIR` that is not absolute, or that is `/`, adds no prefix. The hook denies a path in the repository, a relative path, and a path with a `$`, because the Write tool does not expand a variable. Each deny exits 2, and the message names the path. With no `python3`, or with no file path in the input, the hook fails closed. The hook carries the marker `# agent-definitions:verifier-write-guard`, which the [**validator**](../glossary.md#validator) looks for.

On OpenCode the `edit` permission covers the write, edit and patch tools. OpenCode matches an `edit` rule against the path relative to the [**worktree**](../glossary.md#worktree), and an `external_directory` rule against the absolute parent directory of a path outside the project. The verifier gets an `edit` map that opens with `"*": deny` and allows only `../*`, a path outside the project, and an `external_directory` map that opens with `"*": deny` and allows only `/tmp/*`, `/private/tmp/*` and `/var/folders/*`. An OpenCode pattern holds no variable, so `$TMPDIR` is not in the map. On a host whose `$TMPDIR` is not under one of these prefixes, the two harnesses permit different paths: Claude Code permits a write to `$TMPDIR`, and OpenCode denies it. OpenCode denies each `edit` of a path in the project, and the project is the git toplevel of the working directory, so a worktree in a temp directory stays read-only there too, when the path has the spelling of the real path. OpenCode takes the real path of the project, with each symbolic link resolved, and compares it as text with the path that the agent gives. A path through a link to the project is outside the project as text, so the two maps allow it. Measured on OpenCode 1.15.10 on 2026-10-19 on macOS: in a repository at `/var/folders/<x>/copy`, the write tool wrote a file of the tree through `/var/folders`, and it denied the same file through `/private/var/folders` and through a relative path. An OpenCode pattern holds no variable that names the project, so no rule of the maps can deny that spelling, and the rendered OpenCode verifier states this limit. The verifier stays read-only on the repository and the worktree in both harnesses, except for this OpenCode limit.

The OpenCode `bash` map of the verifier is smaller than the table. It has no `echo` rule, no `printf` rule, no `env` rule, no temp-write command and no [**GET-only command**](../glossary.md#get-only-command). It ends with the deny rules `*>*`, `*| tee *` and `*|tee *`, so it also denies `2>&1` and `2>/dev/null`. A redirection after a group, a subshell, a loop or the last command of a pipeline is not in the text that OpenCode matches, so no rule can deny it. See [the permission rules](opencode-adapter.md#the-permission-rules).
